# LFM2.5-2.6B

## Overview

Liquid AI released LFM2.5-2.6B on 2026-08-04: an open-weight 2.69B-parameter model with a 131K context window, agentic post-training and packaged support for local/edge-oriented execution through llama.cpp, MLX, ONNX, vLLM and SGLang. Its documented tool-use template and OpenAI-compatible serving route make it a candidate for small, high-volume tool loops rather than a general coding-model replacement. ^[raw/articles/liquid-lfm25-26b-2026-08-04.md]

## Relevance and adoption boundary

The primary source says its agentic RL used real harness environments, including [[entities/tools/hermes-agent]], and the release provides the artifacts needed to test a local endpoint. The independently observed launch discussion is early, so the model should be treated as a **controlled trial candidate**, not proof of broad adoption or coding reliability.

The model card explicitly says it is **not recommended for agentic coding or knowledge-heavy tasks**. For Caio, retain a stronger coding/reasoning model for implementation and use LFM only in a bounded, measurable lane such as cheap local classification, extraction, simple tool orchestration or background summaries. Compare it against [[entities/models/bonsai-27b]] and apply the task-boundary/evidence discipline in [[comparisons/model-routing-hermes-opencode-pi]].

## Trial protocol

1. Serve a quantized artifact behind an OpenAI-compatible local endpoint and run a fixed, non-sensitive task set.
2. Measure tool-call syntax validity, completion quality, latency, memory and failure/retry rate separately from coding outcomes.
3. Keep the lane read-only or sandboxed; promote only if it beats the current local baseline on the defined task, not on vendor aggregate scores.
